# 皮肤商城

首页的“皮肤商城”以及暂停/通关页都可进入。预览入口是根目录`试玩皮肤商城.cmd`，使用隔离档案，不写正式成长或巡游币。

当前只有原初奶蛙外观。未来皮肤显示待上架，不能扣币或领取；用户提供具体皮肤后再制作外观和对应动作。

## 获取规则

同一款皮肤可以启用两条路径：

1. 等级和累计吞噬文件大小**同时达标**，自动收入衣橱；不消耗吞噬量。按真实回收记录累计，虚拟碎片不冒充文件大小。
2. 使用通关取得的巡游币购买，不要求满足成长门槛。已经拥有、资源尚未就绪或成长已可免费获取的皮肤，不会重复扣款。

首通/重游币：苔光120/30，荧菌180/45，风暴240/60，熔炉300/75。失败无奖励；每轮有唯一结算ID，重复回调只发一次。同一关的新一轮通关发重游奖励。奖励在`wardrobe/catalog.gd`集中调整。

## 后续上架配置

`wardrobe/catalog.gd`的每个新皮肤条目包含：

| 字段 | 含义 |
| --- | --- |
| `id` / `title` | 永久稳定的ID与显示名称 |
| `published` | 资源完整并完成适配后才启用 |
| `preview` | 原图/预览的资源路径 |
| `combat_manifest` | 游戏侧动作素材清单路径 |
| `desktop_manifest` | 桌宠侧动作素材清单路径 |
| `growth` / `level` / `bytes` | 是否支持成长解锁，以及同时需要满足的门槛 |
| `coins` / `price` | 是否支持巡游币购买，以及正整数币价 |

缺少预览或任一端清单的未完成商品会保持不可获取。当前目录的三张预约卡没有设定真实名称、价格、等级或吞噬门槛。穿戴ID已可持久保存；新皮肤的实际桌宠/战斗渲染接入随素材一起完成。

## 保存

`%APPDATA%/NaiwaFragmentPrototype/wardrobe.json`保存版本1的币余额、累计获得/花费、分关通关次数、已结算轮次、已拥有ID与穿戴ID。使用`.tmp`、`.bak`；损坏主文件尝试备份，新版本存档保护为只读。保存失败不会出现扣币却未拥有的半笔交易。

旧`profile.json`不改变结构。主界面原等级和吞噬量继续有效；币与关卡徽记从本版本的首次记录开始计算。
