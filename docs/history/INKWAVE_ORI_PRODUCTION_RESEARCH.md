# 奶蛙：INKWAVE 菜单、柔光童话场景与动作制作研究

研究日期：2026-10-28。阶段：资料、源码审查与制作方案；本轮没有替换游戏资产、安装插件或改动运行时代码。

## 已确定的方向

- 用户指定的菜单参考是 [amiaoapp/inkwave](https://github.com/amiaoapp/inkwave)，不是任天堂游戏源码，也不是此前搜索到的同名 UI 组件库。
- 场景和战斗 HUD 采用前面“柔光童话”的《奥日与萤火意志》方向；菜单保留 INKWAVE 的活力，战斗区域强调空间层次和可读性。
- 保持原版奶蛙的脸、头身比例、黄色情调、肚子轮廓与材质；动作不能靠换一只近似角色实现。原版桌宠继续使用原始完整素材与交互。
- 继续横版战斗、虚拟文件喂食、共享成长、进入游戏和返回桌宠。
- 本文中的敌人名称、招式、配色和时长属于本项目的设计提案，不是参考游戏已经实现的效果，也不是本项目已经完成的效果。

## 研究得到的关键结论

### 1. 奶蛙的问题首先是动作资产，其次才是播放系统

本地 `desktop/素材.nwp` 有 450 项：449 张 PNG、1 个 JSON；检查 `references/Naiwa` 没有发现 blend/glb/gltf/fbx/obj/psd/ora 模型或分层文件。原有笑声、眨眼等动画不等于跑步、出拳和踢击动作资产。

目前 `prototype/v3/naiwa_visual.gd` 给完整站立图建立网格，`naiwa.gdshader` 用位置范围推移脚、手和上身。它没有真正独立的前后肢体、隐藏关节和替换姿势。增加推移幅度会把皮肤、肚子或关节一起拉坏；增加插值只能让这种变形更平滑。

另外，当前 `contact_error` 只取两只脚局部纵向偏移的较小值。这个指标不能证明世界坐标下的脚没有横向滑动，也不能证明图像中真正的脚底贴地。先前“着地检查通过”应理解为这一个有限条件通过，不能作为动作质量验收。

推荐路线：**沿用原图的分层骨骼动画 + 大动作的替换部件/校型关键帧**。

1. 建立角色锁定稿：原版站姿、面部、头身比例、手脚尺寸、肚子外形、材质和光向作为对照。
2. 从原素材拆出头、躯干、骨盆、近远上臂/前臂/手掌、大腿/小腿/脚。保留可用原像素，补齐遮住的肩、肘、胯、膝和躯干；先检查拼回站姿是否一致。
3. 使用 `Skeleton2D/Bone2D` 与分层 Sprite/Polygon 绑定。脸和主要身体轮廓以刚性部件为主，权重只在必要关节小范围混合。
4. 出拳、踢击、明显侧转使用替换手脚和校正姿势，修复遮挡及透视；不要求一张 PNG 承担所有角度。
5. 用 `AnimationPlayer` 保存经过设计的姿势和事件，`AnimationTree` 管状态混合。日常运动衔接可以柔和，攻击峰值要保留速度变化。
6. 若以后取得可用的原始模型与许可，可从同一模型、材质、固定相机输出动作。现阶段不把“重建一个差不多的 3D 奶蛙”当作保持形象的替代品。

[Godot cutout 文档](https://docs.godotengine.org/en/stable/tutorials/animation/cutout_animation.html) 明确支持骨骼剪纸与手脚等局部逐帧替换结合；该页仍有未更新至 4.7 的提示，具体 API 以本地引擎验证为准。[AnimationTree 文档](https://docs.godotengine.org/en/stable/tutorials/animation/animation_tree.html) 提供状态机、同步切换、混合曲线和 OneShot。

### 2. INKWAVE 的动作方法有价值，但不能把它的骨架直接套在奶蛙上

读取了指定仓库的 `docs/RIG.md`、`src/game/character.js`、`src/boss/bossAnim.js` 与 `docs/BOSS.md`。该项目使用 three.js 的 3D 蒙皮骨架和程序化姿态，奶蛙现有工程是 Godot 4.7.2 Compatibility，资产条件也不同。

可移植的方法：

- **按真实位移走路**：步频和落点跟随角色实际移动，急停有收脚，转向有换重心。
- **支撑脚固定在世界坐标**：落脚时保存接触点；身体向前走时脚仍停在那里，直到蹬地。IK 负责让膝盖和腿连接到这个目标。
- **分层运动**：主姿势先确定，再叠加有限的胸腹、手臂跟随和落地缓冲；弹簧用于次级运动，不把整个人物做成果冻。
- **同一招式时间轴**：预备、有效攻击、恢复阶段同时驱动姿势、判定、声音与特效。换段、受击、死亡和切回桌宠都有明确处理。

源码证据：`character.js` 的 `_footPose()` 在支撑期直接保持 `f.pw`；应用姿势时把世界接触点换算到角色根坐标；`bossAnim.js` 按实际根位移推进步态。这比只将脚的 y 设置为地面高度完整得多。

### 3. “丝滑”需要连续与节奏同时成立

拟制作动作：待机、起跑、跑步循环、急停、转向、起跳、滞空、落地、三段普通攻击、蓄力重击、闪避、受击、大招、倒地/恢复。

- 跑步循环保持左右脚相位，速度改变时渐调步频，停止时选择支撑脚落稳；不能每次状态切换都从第一帧重新跑。
- 普通衔接可从约 60–120 ms 混合时间起调；攻击命中姿势单独处理，不能被长时间混合冲淡。这些是初始调参值。
- 招式有重心移动和肩肘腕的先后关系；蓄力慢、释放快、收招有惯性，不能所有关节同速插值。
- 允许在明确窗口缓存下一次攻击；只有指定恢复阶段可以取消到闪避。伤害时刻不能由视觉混合权重随意改变。
- 物理保持固定步进，显示端平滑插值；60 FPS 是播放目标，不是动作质量的替代品。极短的命中停顿是有意的力量节奏。
- 左右朝向、急转、被击退、跳落地都要逐帧查看脚和关节。Godot 旧版本确实有镜像骨骼修改问题，但相关 issue 已关闭，Jiggle 的 [PR #117611](https://github.com/godotengine/godot/pull/117611) 已合并，不能因此断言当前版本一定有同样缺陷；应测试本项目的绑定方式。

## 菜单：以 INKWAVE 为准制作，而不是只换一套颜色

实际访问了仓库 README 链接的 [在线示例](https://inkwave-aah.pages.dev/)，进入主菜单并查看模式页；同时读取 `src/ui/menus.js`、`styles/ui.css`、`src/ui/menu-art.js`。在线版本可能落后仓库：看到的是两个模式，main 源码已有更多配置。

值得保留的结构：左上标题，左侧主要动作，右侧角色/进度信息，底部按键提示；主要动作明显更大，次要动作有轻微错落倾斜。源码还有焦点记忆、返回栈、按顺序入场和减少动态效果支持。

本项目主菜单拟映射为：

| 位置 | 奶蛙版本内容 | 设计要求 |
|---|---|---|
| 左上 | 游戏标题与小标记 | 定制中文标题排版；不照搬英文 Logo。 |
| 左侧首项 | 继续冒险 / 开始冒险 | 最大按钮，清楚的选中轮廓、短暂压下回弹。 |
| 左侧后续 | 喂食成长、招式、设置、返回桌宠 | 辅助图标、轻微倾斜；不要所有入口同等突出。 |
| 右侧主体 | 原版奶蛙全身与场景 | 保留腿和脚的完整轮廓，不用半身裁切掩盖问题。 |
| 右侧小区块 | 等级、经验、当前招式 | 信息控制在必要范围，避免回到仪表盘大面板。 |
| 底部 | 选择、返回、桌宠快捷提示 | 键盘与手柄焦点一致，中文可读。 |

实现用 Godot `Control/Container`、主题与独立动效节点。参考 INKWAVE 的入场延迟和弹性曲线，不把 CSS/DOM 原样搬进桌宠宿主。标题字和中文正文分工，选用覆盖中文且许可清楚的字体，不能直接沿用只含拉丁字符的字体包。

菜单与场景的连接建议：用奶蛙原有暖黄色、深蓝绿、少量乳白光作为共同色板；菜单增强对比，战斗收敛装饰。墨迹转场可设计成“碎片汇聚/散开”的自有图形，与文件成长主题相连。所有图标、按钮边缘、音效与转场共同设计，避免孤立拼贴。

## 场景与战斗 HUD：柔光童话，也要有锋利的战斗焦点

参考 [奥日官方媒体](https://www.orithegame.com/media/) 和此前已经查看的实机图。GDC 的美术讲座检索到了，但本次打开落到维护页，未声称看完视频。

第一个场景提案：**萤光林地中的遗忘书庭**。远处巨树与书庭轮廓形成主景，近处树根/石阶构成明确战斗地面。原版奶蛙的暖黄成为第一视觉焦点。

- 五层组织：远方天空/雾、巨树主景、树根与书庭、中景战斗地面、少量前景叶片。远景对比低，中景轮廓清楚，前景不遮攻击路线。
- `Parallax2D` 提供层间移动；手绘/精修场景纹理负责形状和材质；局部光源、接触阴影与光束负责空间关系。不是给现有方块统一加模糊和发光。
- 奶蛙原图已经包含光影，新增灯光要避免把脸和黄色照成另一种形象；先检查同一画面中的主光方向与脚底阴影。
- 战斗 HUD：左上生命/体力，下侧小型招式/能量图标，Boss 战才出现上方 Boss 条；平时不常驻文件列表、大卡片和营地说明。
- 场景冷色压低饱和度，角色暖色突出；敌方危险用色配合形状和动作提示，不能仅靠红绿区分。

技术参考：[Godot Parallax2D](https://docs.godotengine.org/en/stable/tutorials/2d/2d_parallax.html)、[2D 灯光和阴影](https://docs.godotengine.org/en/stable/tutorials/2d/2d_lights_and_shadows.html)。资产本身需要制作，插件不能自动得到《奥日》的画面质量。

## 敌人逐个设计，不再复用一个人偶换颜色

先做一个敌人完整闭环，再扩展。以下是一组可与林地/遗忘书庭协调的原创方向，名字暂定：

| 敌人 | 外形与材质 | 动作和招式 | 提示、反制与反馈 |
|---|---|---|---|
| 苔刃猎兽：近战追猎 | 低伏四足，肩背长叶刃，前肢较重；苔绿硬壳与暗色软腹，侧面呈楔形 | 缓步盯人、压肩蓄力、短扑、落地回身；攻击后前爪先落稳 | 扑前压低肩膀并翻起背刃，锁定方向后不瞬间转弯；躲过后可打侧腹；破甲飞出叶壳而非通用方块。 |
| 提灯蛾：远程控制 | 不对称长翼和下垂灯囊，上宽下窄；半透明翼膜与微亮腹部 | 翅膀先收拢聚光，再展开射出窄扇弹；受近身威胁后退，有间隔 | 灯囊聚光提示扇形方向，弹间保留穿行缺口；打断蓄力后短暂坠落；受击掉少量翼粉。 |
| 折页卫：精英决斗 | 高瘦覆面，折页披肩，单侧长刃；旧纸、铜扣、暗色内衬形成明确材质层级 | 试探步、横斩接回挑、后撤；偶尔格挡，重击可破防 | 每段动作可辨，第二段不是无提示追加；诱出完整连招后有较长收招；破防是披肩散开和武器偏转。 |
| 暮冠守卫：Boss | 树根与层叠书脊构成厚重躯干，分叉冠部、偏重一侧的长臂；轮廓有高低变化 | 一阶段横扫/砸地，二阶段新增延迟根刺和冲锋；阶段变化在招式之间发生 | 冠部与肩臂先给预告，砸地波可跳、冲锋可躲，撞墙后核心暴露；变化增加组合和场地压力，不只是加血。 |

每个敌人需要：剪影稿、材质/配色稿、待机与移动、各招式预备/有效/收招、受击/破防、死亡，以及对应音效/特效清单。轮廓缩小到实战尺寸仍应能区分；招式关闭粒子后仍能读懂。

首轮先完成“苔刃猎兽”。后面几个按同一标准分别制作，不在它没做好时用更多占位敌人填数量。LimboAI 的游击、侧翼和冷却示例可帮助行为实现，角色造型仍是独立美术工作。

## 招式、大招与打击感

统一效果语言：奶蛙使用暖金/乳白的锋利轨迹，少量青色余辉；敌人按职责使用独立的形状和危险色。轨迹依附真实手脚/武器路径，命中爆发发生在接触点。

| 动作 | 动作设计 | 效果节奏提案 |
|---|---|---|
| 普攻三连 | 小幅进步拳 → 横向摆击 → 蹬地踢击；第三段有明显重心转换 | 短而窄的弧线，接触点亮核与少量碎屑；第三击扩大方向性冲击，声音分三层强度。 |
| 蓄力重击 | 后脚支撑、重心后移、聚力后向前释放 | 光从手/脚附近收束，蓄满出现清楚提示；命中才出现主爆发，落空只保留运动轨迹。 |
| 闪避 | 压低身位、短促启动、恢复站姿 | 短寿命残影与贴地尘；残影必须来自当前完整姿势，不能用一张静态站姿盖上去。 |
| 大招“碎光破晓” | 稳定支撑 → 聚拢碎光 → 前踏释放 → 收势；不变身、不改脸、不永久改变身体 | 约 0.35–0.55 秒局部聚光，主爆发沿前方推进，随后碎片和余辉快速退场；与有效范围同步，保留敌人轮廓和危险提示。 |

这些时长是待试玩调节的初值。普通命中可从约 30–50 ms 局部停顿、重击 60–90 ms 起调；不能每次粒子碰撞重复停顿。镜头响应沿冲击方向，音效分出挥动、接触与低频力度，命中与挥空明显不同。

普通轨迹使用 `Line2D`/自制网格、动画贴图与有限粒子；复杂大招再评估 Effekseer。残影应截取已经组合好的骨骼姿势，GDQuest 的单 Sprite 示例需要适配，不能直接假设支持新角色结构。大招失败或取消时应能清理光效、震动和未触发的伤害事件。

## 制作顺序与验收

1. **角色资产与动作小样**：锁定原形象，完成分层站姿、跑步、急停、一次出拳和一次受击；在灰色地面上观看原速与慢放。此阶段只为验证绑定与动作，不用场景遮住问题。
2. **一个完整敌人 + 30 秒战斗片段**：加入苔刃猎兽，先看预备、落脚、打击、破防和死亡能否相互衔接，再加特效。
3. **菜单与场景样稿**：分别做 INKWAVE 布局的中文菜单、柔光书庭的战斗构图；奶蛙、敌人、地面、HUD 必须一起呈现，以便判断是否统一。
4. **招式与大招定稿**：按动作时间轴制作，验证命中位置、可读性、遮挡和连续释放时的性能。
5. **拓展其余敌人与难度**：先增加招式组合、攻击间隔和反制机会，再调生命伤害；完成桌宠切换和成长回归验证。

验收标准：

- 原版对照：站姿能看出是同一奶蛙；脸、头身比、手脚尺寸和颜色不漂移；动作中无断肢、撕裂或腹部被拉长。
- 脚部：支撑期记录实际接触点的世界坐标；以原生画布约 1–2 像素的非预期滑移/离地为初始容差，明确排除蹬地、跳跃、击退等设计动作；截图验证可见脚底，不只检测目标点。
- 连贯性：左右跑、急停、转向、落地接攻击、受击打断、攻击接闪避，在正常速度和逐帧下均无突然跳姿；曲线混合不造成腿穿过身体。
- 判定：有效帧与手脚轨迹同步；同一招对同一目标不重复计算错误伤害；粒子不能创造额外命中。
- 识别度：关闭粒子、换为灰度、缩至实战大小后，角色、敌人预告和可走地面仍清楚。
- 性能：在用户机器、目标分辨率实测战斗与大招的帧时间；目标 60 FPS，不能把空场景或平均帧率当作重负载通过。
- 菜单：中文标题不混用突兀字体；键鼠/手柄焦点、返回、音量与减少震动效果有效；16:9、16:10 和窗口缩放下无重叠。
- 回归：原版桌宠完整显示；进入/返回仍是同一局；成长保存正确；只使用虚拟文件。

研究完成不代表动作资产或视觉效果已经完成。最先需要投入制作的是奶蛙分层与关键姿势；这一环节做不好，换 UI 框架、动画插件或增加粒子都无法补救。
