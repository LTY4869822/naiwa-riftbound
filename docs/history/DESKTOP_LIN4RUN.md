# LIN4RUN桌宠与游戏联动

2026-10-28。默认桌宠使用用户指定的 [LIN4RUN/naiwa-desktop-pet](https://github.com/LIN4RUN/naiwa-desktop-pet)，接入 `prototype/v5/slice.tscn`。本轮交互是直接把文件拖到奶蛙身上，吞下后移入Windows回收站，并按成功处理的大小成长。

## 日常使用

双击 `启动奶蛙原型.cmd` 或 `拖文件喂奶蛙.cmd`。把不再需要的文件或文件夹拖到奶蛙身上松开，即可看到张嘴、吞咽和大小反馈。成功回收的原文件可在Windows回收站中还原。

右键菜单显示“Lv.等级 · 累计吞噬大小”和“距下一级还需大小”。选择“进入游戏”或双击 `进入奶蛙游戏.cmd` 进入横版游戏；P返回桌宠，再进游戏继续当前会话。游戏的“吞噬成长”页显示累计量与大小进度，并提供返回桌宠按钮。

这些入口统一使用 `desktop/lin4run/奶蛙桌宠-联动版.exe`。旧的 `回收站补给.cmd` 与 `--recycle` 参数兼容为 `--feed` 提示入口。已运行旧版桌宠时需要先正常退出，再打开本版；启动器不会强制结束已有会话。

上游的眼睛跟随、眨眼、422帧大笑、行走、拖动与重力、上抛哭泣、待机小动作/转手舞、睡觉、群体表演、饥饿反馈、音量、托盘和右缘隐藏继续保留。上游饥饿值用于桌宠动作与表情，游戏等级使用下面的共享成长规则。

## 大小与升级

界面以字节大小显示成长，不要求分类或逐项勾选。内部沿用已有游戏曲线与存档，避免创建第二个角色等级：每累计8 MiB成功大小转成1点内部经验，余数保留；等级L的升级需求是`60 + 30 × (L - 1)`点。

在没有战斗或其他既有经验时：

| 升级 | 该级新增吞噬量 | 从Lv.1开始的累计量 |
|---|---:|---:|
| Lv.1 → Lv.2 | 480 MiB | 480 MiB |
| Lv.2 → Lv.3 | 720 MiB | 1200 MiB |
| Lv.3 → Lv.4 | 960 MiB | 2160 MiB |

战斗经验仍加到同一个等级，所以已有经验会减少还需吞噬的大小。只计确认回收成功的逻辑大小，零字节文件不额外产经验，取消/跳过/失败的项目不计入。显示的大小不代表精确释放的物理磁盘空间。

桌宠会把尚未由游戏确认的成功收据加入只读投影，立即显示预计等级、累计量和距下级余量。Godot启动后自动导入并持久化正式等级；游戏运行时也会自动同步。等级最高1000，已确认的累计大小仍可记录。

## 文件处理范围

输入来自用户拖放的绝对本地路径。普通文件夹会递归测量内部文件元数据，整份文件夹成功回收后才计入其总量；同时拖入父文件夹和内部文件时只计父项。

- 单次最多1000个顶层文件/文件夹，合计32 GiB；测量限制文件夹层级和内部项数，过大的树会跳过。
- 符号链接、重解析点、云端占位项及其所在的重解析路径会跳过。普通`.lnk`是普通文件时只回收快捷方式本身，不跟随目标。
- 磁盘根目录、网络/非固定磁盘、系统保留目录、系统/游戏/程序数据目录及这些目录的父目录会跳过；整个桌面、文档、用户目录也会跳过，里面单独拖入的普通文件可按规则处理。
- 测量与实际回收前核对路径和元数据快照；项目在期间发生变化时保留原位，不推定成功。

Windows适配层使用 `IFileOperation` 的可还原回收标志与逐项回调，不提供永久删除后备路径。只有确认Windows返回整项回收成功、已产生可验证的回收项且源位置移除后才出具成功结果；系统不允许安全回收的项目不计成长。后台STA执行文件操作，桌宠和游戏桥接心跳保持响应。

## 记录、迁移与恢复

| 位置 | 用途 |
|---|---|
| `%APPDATA%\NaiwaFragmentPrototype\profile.json` | Godot共享等级与账本；`.bak`为有效备份 |
| `%LOCALAPPDATA%\NaiwaDesktopPet\settings.ini` | 桌宠大小、位置、声音等设置 |
| `%LOCALAPPDATA%\NaiwaDesktopPet\recycle-feed\receipts\` | 不可变的成功收据 |
| 同级 `drop-transactions\` | 本轮拖放投喂的意图与成功记账 |

旧的等级、经验、背包和版本1/2档案继续兼容；旧投喂收据也继续导入。游戏菜单的日常操作已经统一为大小成长，历史虚拟背包字段留在存档中用于兼容。

桌宠不写游戏主存档。它先检查记账目录可写并落盘意图，按已确认的逐项结果保存成功证据，再发布整批成功收据。收据只含摘要ID、字节数、时间与协议字段，不含真实文件内容、文件名或原位置。Godot将成长与收据/条目去重账本一起保存，成功后保留源收据作为持久证据。

正常使用桌宠启动器保持单个游戏会话，Godot是主存档唯一写入者。外部手工多开游戏进程并同时写同一存档不在支持范围。

如果回收成功后记账暂时失败，桌宠保留待保存状态并重试记录，重试不会再次回收文件。进程重新启动时只恢复已落盘的成功证据。Windows回收与本地记账不能构成跨系统绝对原子事务；在回收完成而成功证据尚未落盘的窗口发生崩溃，可能漏记成长，程序不会仅凭源文件消失推定奖励。它也不会在恢复过程中重新移动文件。

## 拖入时显示修复

拖放动画原来在首次悬停时同步解码全部120帧，失败时可能只画出透明窗口；现在按需解码并最多缓存12帧，单帧失败或素材不可用时回退显示待机角色。拖拽、吞咽、后台处理和短暂反馈期间会保护窗口可见，避免全屏自动隐藏误触发；鼠标按下期间也暂停自动行走，方便把文件拖到角色身上。普通全屏隐藏在投喂结束后仍生效。

在当前机器上的隔离基准中，首次准备并显示拖放帧从658ms降到7ms。隔离拖入检查通过，并在50%、85%、100%、150%大小下检查了56个悬停窗口与画面样本；没有拿用户文件做这些显示测试。游戏返回桌宠改为最小化主窗口、继续时恢复窗口，桥接测试确认原进程复用且窗口状态正确。日志分别在 `prototype/artifacts/lin4run-visibility-final/pet-feed-ui-tests.txt`、`prototype/artifacts/hover-fixed-3aad8f9c813d4e72ab7daeace5cd7a03/result.json` 和 `prototype/artifacts/lin4run-bridge-visibility-final/bridge-test.txt`。原始问题未能在隔离环境中直接复现，因此这次修复针对查到的潜在触发路径，仍需要实际拖放反馈确认。
