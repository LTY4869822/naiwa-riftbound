# 苔光遗境：战斗 HUD 美术方向

2026-10-28。为奶蛙正式游戏中的生命、体力、技能、首领和状态提示制定的实现方向。此文是设计与源码审计；完成情况以游戏代码、运行日志和实机截图为准。

## 参考与实际查看范围

参考其他游戏的信息组织与造型方法，最终图标、边框和排版由奶蛙项目重新绘制，不下载或导入其他游戏的 HUD 美术。

1. [Hollow Knight 官方网站](https://www.hollowknight.com/)及其直接链接的 [Grimm 官方实机图](https://images.squarespace-cdn.com/content/v1/606d159a953867291018f801/3d24e1c8-d368-4b05-bb5f-00888e238d12/Grimm.jpg)。实际查看了图像：灵魂圆容器、横排生命面具和少量货币数字集中在左上，画面中央及角色附近保持干净。可借鉴独特轮廓与留白，不能据此声称该图有 Boss 血条。
2. [Ori 官方媒体页](https://www.orithegame.com/media/)的 `Screenshot Ori and the Will of the Wisps E3 2019 01`。实际打开了官方截图弹窗；这张是无 HUD 的宣传构图。因此本轮只取其青绿深景、乳白局部光、柔和边缘与空间留白，不将它当作已核实的血条样式依据。
3. [Supergiant 的 Hades 官方页面](https://www.supergiantgames.com/games/hades/)及其 gallery 链接的 [2019 官方实机图](https://images.ctfassets.net/5owu3y35gz1g/5LpElH2nmE7iS4v593VJvo/55f74bd209f45dc179c5279926cb2ea5/hades_09-dec-2019_05.jpg?w=1920&q=80)。实际查看了图像：左缘菱形能力符号、左下装饰性细长生命条与当前/最大数字、上方中央较薄的首领血条，低生命用边缘红光增强提示。可借鉴材料层次和关键数字的主次，不照搬其希腊纹样、图标或红色主题。

这是观察后作出的本项目适配建议；尺寸和动效时长不声称为上述游戏的源码实值。

## 本项目的视觉选择

菜单沿用此前确定的 INKWAVE 活力风，进入战斗后采用已经确定的柔光童话方向，与本游戏苔光遗境背景匹配。

- 基础是深蓝绿的半透明承托面，减少目前大块不透明矩形。
- 奶蛙身份使用暖金勋章和局部奶白高光；生命用翡翠/薄荷的双层填充，体力用纤薄暖金线；技能专注用青白碎光。
- 首领条采用暗玫瑰金与温和珊瑚色，靠皇冠/叶冠轮廓区分身份。装饰集中在两端，不包围整片战斗画面。
- 所有重要文字要有稳定的深色底或描边；不能仅靠外发光抵抗复杂背景。
- 对称微饰、叶尖、碎片切面可重复作为图形语汇。避免每个区块使用不同的边框系统。

## 建议构图

以下按已有 1280×800 设计画布说明，最终组件应锚定边缘/中央并随画面缩放，不将这些坐标当作所有分辨率的硬规则。

| 区域 | 建议范围 | 信息优先级与样式 |
|---|---|---|
| 左上伙伴状态 | 左/上安全边距约24；总宽350–380，高100–115 | 左侧直径64–72的暖金头像勋章；右侧角色名/等级、较粗翡翠生命条、纤细体力条；生命当前/最大值保持可读，不让填充覆盖数字。 |
| 上中地点与目标 | 中央宽220–280，高55–65 | 地点名为主，波次/击破数为副。细分隔线与小碎片符号即可，无需整块卡片。 |
| 上中首领条 | 中央宽460–520，约y125–180 | 仅出现真实活着的首领时显示；名字在条上方，状态短句在下方；条厚12–16足以观察损血，尾端保留空槽和迟滞伤害。 |
| 右上系统按钮 | 右/上安全边距约24 | 紧凑的暂停、桌宠按钮，图形和短键提示并存；不与地点争夺最大字号。 |
| 底中技能 dock | 总宽约420–500，高90–110 | J/K/L/U四个精绘菱形或圆钻勋章，按键明确；U稍大，展示专注环与60点可用阈值；键名与技能名分层。 |
| 底左操作 | 小块两行或一行 | 移动/跳跃和Tab补给提示收敛，视觉权重低于技能状态；可以在首次进入后弱化。 |
| 状态/消息 | 底部技能区上方或上左空位 | 同时最多一条主要状态，不常驻长教学段落；需要消退与互斥，避免说明压住技能栏。 |

现有场景战斗地面约在y640。中间约y210–660是角色、弹体、前摇和落脚的主要可见范围，应保持干净。装饰性技能盘收在其下方；首领条可在上方空景区。按本项目最小960×600窗口查看后，需要保住关键数字和按键名，不能只在1152×720截图上读得清楚。

## 源码对应的真实状态

已读 `prototype/v5/fighter.gd`、`enemy.gd`。

| 显示 | 可用字段或规则 | 不应伪造的内容 |
|---|---|---|
| 生命 | `player.hp`，上限 `Profile.max_health()` | 不能将固定100当成升级后的上限。 |
| 体力 | `player.stamina`，上限100 | K重击消耗28，L闪避消耗32；不是每个技能都用体力。 |
| 专注 | `player.focus`，上限100；U需`Profile.level>=2`且`focus>=60` | 100才亮的整环会误导玩家；60点阈值必须可感知。 |
| 闪避冷却 | `player.dash_cd`，施放后设为0.55秒 | K重击和U不存在独立计时冷却，不为好看画假秒数。 |
| 连击 | `player.state=="attack"`、`player.combo`为0/1/2、`elapsed` | 可做三个小花瓣/切痕，只在真实连击期间点亮，不捏造攻击次数。 |
| 玩家状态 | `state`含idle/attack/skill/hurt/dash；`invuln` | 受伤保护、闪避、技能施放可用短词或小图标；不要新增中毒/燃烧/护盾等未实现状态。 |
| 首领 | 活敌`kind=="boss"`、`hp/maximum` | 普通敌人不触发常驻首领条；首领死亡后应收起。 |
| 首领动作 | `state`含approach/tell/active/recover/stunned | 可映射为巡视/蓄力/攻击/收招/破势。`tell/active`时抗轻击可提示重击破势，但不是永久无敌。 |

`player.changed`在现有物理更新中发出，HUD应从该信号或host的既有刷新入口接受数值，再独立驱动显示插值。显示动画不能改写战斗数值。

## 反馈建议与边界

- 受伤：实际生命立即更新，迟滞色段可停约0.25–0.35秒，再在0.6–0.8秒内跟随；让玩家看到刚损失的份额，而非把整个HUD晃动。
- 低生命：建议25%阈值，用边框脉动、警示形状与短文字共同提示。减少动态开启后保留静态警示，关闭呼吸/震动。
- 体力不足：仅相关技能变暗，并显示不足的短标签；不要把J普通连击一并禁用。
- 专注可用：达到60点时给U一次细小涟漪/描边增强；持续可用期间不反复爆发粒子。
- 计时冷却：闪避环从0.55秒按实际剩余时间擦除，结束一瞬轻亮。技能施放/锁定/资源不足分别有不同形状或标签，避免全部灰色。
- 数字与文字不随填充宽度移动，不随着血量下降被裁切。伤害迟滞色不能盖住生命的实际填充。
- 灯蛾在右侧中高位置、首领较高，HUD状态条不能遮挡其瞄准线和起手；不要把锁定目标卡放在角色头顶持续挡招。

建议同时检查满血、受伤、低血、缺体力、U锁定、U可用、闪避冷却、首领蓄力/破势、暂停、胜败和最小窗口，而不是只交付满血静态画面。
