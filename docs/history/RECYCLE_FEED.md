# 回收站补给：让奶蛙吞噬垃圾文件并成长

2026-10-28。此功能已接入Windows桌宠；回收站补给与游戏里的虚拟碎片补给分别计量，共用奶蛙的游戏等级。

## 打开与使用

1. 双击 `file-feeder/回收站补给.cmd`。也可打开 `desktop/奶蛙桌宠-回收站版.exe`，右键奶蛙或托盘图标，选择“回收站补给”。若旧版桌宠仍在运行，请先用其右键菜单退出，再打开升级版。
2. 窗口读取**当前用户Windows回收站**的文件元数据：名称、原位置、删除时间、逻辑大小和支持状态。默认不勾选任何文件，不读取文件内容，不扫描整个磁盘。
3. 逐项勾选确实不再需要的普通文件，查看本批处理大小和预计经验。文件夹、链接、重解析点和无法验证元数据的项目不可投喂；单批最多1000项、32 GiB。
4. 应用强制勾选“永久删除”确认，并点击“永久吞噬所选文件”。程序请求Windows显示永久删除警告，实际提示以系统为准；若系统显示确认/进度窗口，可以取消。
5. 只在Windows确认实际成功且再次核实已从回收站移除后，才保存该项的成长记录。取消、跳过、失败、已经变化或无法核实的项目不计经验。

**吞噬是真正从回收站永久删除所选文件，不能再用回收站的“还原”恢复。** 未选择、未确认时只有预览；没有后台自动删除或定时清空。

## 经验与升级

累计每 **8 MiB（8×1024×1024字节）=1 XP**，不足8 MiB的余数会保留到下一次，不按每个文件额外赠送最低经验。因此多个小文件也可以慢慢累积，空文件不会凭数量刷经验。

例如：先成功处理5 MiB，再成功处理3 MiB，共获得1 XP。在Lv.1且当前0 XP、没有其他经验来源时，累计成功处理 **480 MiB** 可得到60 XP，升到Lv.2。已有的战斗或虚拟碎片经验也参与同一条升级曲线，所以实际所需回收站大小可能更少。

窗口显示的是文件逻辑大小，不将它直接等同于精确释放的物理磁盘空间。压缩、稀疏文件、硬链接和文件系统分配可能使二者不同。

游戏正在运行时会自动导入成长收据；游戏关闭时，桌宠先保留“待同步”记录，下次进入游戏后同步等级。升级以成功写入游戏存档后的等级为准，窗口中的“成长预览”是尚待游戏同步的预计结果。

## 记录、失败和恢复

桌宠不直接修改正在运行的游戏存档。它把已确认成功的条目写成不可重复的本地收据，由游戏把经验和去重账本一起保存。

- 游戏存档：`%APPDATA%\NaiwaFragmentPrototype\profile.json`；`.bak`为上次有效备份。
- 回收站收据和事务记录：`%LOCALAPPDATA%\NaiwaDesktopPet\recycle-feed\`。
- 记录只包含不直接可读的条目身份、成功字节数、时间和状态等记账信息；不记录文件内容、文件名或原位置。文件名与原位置只显示在本机选择窗口中，没有上传功能。

若部分文件成功、其余取消或失败，只计成功部分。若删除已完成但成长记录保存失败，保留当前窗口并使用“重试保存”；重试只保存记录，不再次删除文件。没有成功项目时不发经验，也不会因为完成标记失败锁死后续预览。

**Windows删除与本地记录无法跨系统组成绝对原子事务。** 删除和成功记录落盘之间崩溃，可能留下无法确认的条目。程序只恢复已有成功证据的记录，不会把“文件已经不见了”推断为自己成功吞噬，因为文件也可能被用户还原或由其他程序处理。此类歧义保守地不自动奖励，不能承诺所有断电时刻都零漏记。

## 当前支持范围

- Windows 10/11桌面环境，使用Windows Shell和当前用户权限；不要求管理员权限。
- 仅当前用户回收站里的、可验证的普通文件。暂不支持文件夹、快捷方式/链接、重解析点及元数据未知项目。
- 不处理下载目录、浏览器缓存、系统目录或其他磁盘中的所谓“垃圾”；未来若扩展，应单独预览和确认，不能沿用回收站选择冒充授权。
- 只做本地成长，不声称收据系统具有联网防作弊能力。

## 开发与验证边界

Native服务的25项fake-store检查覆盖确认、取消、部分失败、预览不可变、防重复、持久化失败、重试与重启恢复。测试中的“删除”全部是内存列表变化。Godot收据导入另用隔离存档与临时收据目录验证；预览演示使用虚构清单。

Windows真实回收站本轮仅做只读枚举和COM绑定检查，**没有对用户真实回收站执行永久删除验收**。不能把fake测试、只读扫描或界面演示宣传成已完成真实清理测试。
