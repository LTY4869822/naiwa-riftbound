# 二维战斗篇：形象保持与动作接回

2026-10-28。按用户「继续完成后续工作，人物不要变形，动作不要僵硬」实现。默认入口为 `prototype/v5/slice.tscn`；原生桌宠仍是上游 Naiwa 的桌面窗口，不是 Godot 伪装的桌宠。

## 本轮实际完成

- 从独立动作验证场接回完整的两波战斗、战利品、虚拟文件喂食、升级、营地往返和原生桌宠往返。
- 奶蛙仍采样原始 PNG；头、脸和躯干只做统一刚体平移/小幅转动，不施加腿部蒙皮权重，不做全角色横纵压缩。
- 膝盖由线性混合改成二维双四元数混合，减轻关节旋转时体积被挤薄的问题。支撑脚坐标排除屏幕震动，避免画面震动反过来扯动腿。
- 停步用 260 ms 的交错收脚过渡，避免直接跳回默认站姿。出拳加入蓄力、快速击出、短暂保持与收势；身体的微小重心变化和手臂略有错相。
- 使用原作者的六张眨眼图，在约 5.7 秒的周期中播放原始眨眼。没有生成新的脸。
- J 有三段连击输入缓存；K 重击破势；L/Shift 闪避；U 蓄力后释放碎片冲击。挥拳音效在出招窗口播放，伤害窗口、击中停顿、飘字和冲击线分层触发。
- 角色姿态和手部判定在同一物理步更新，避免沿用上一渲染帧的碰撞位置。腾空出拳保留空中脚部姿态，不再把脚向地面约束。
- 叶甲兽、灯蛾、古树守卫分别使用近战、远程、首领逻辑；同类近战保留间距，减少两只怪叠在同一位置。敌人有前摇提示、瞄准线和收招空档。
- 背景采用已存在的森林平台画稿，固定横版相机；像素地面与碰撞地面统一。营地和 HUD 保留清晰文字、虚拟文件选择和暂停/桌宠入口。
- 修复两个旧 Windows 启动脚本的中文路径解析问题：明确 UTF-8 代码页并统一为 CRLF，实际通过 `进入奶蛙游戏.cmd` 启动确认。

## 操作

双击 `file-feeder/进入奶蛙游戏.cmd`；也可从原生桌宠菜单进入。

| 按键 | 功能 |
| --- | --- |
| A / D、方向键 | 小跑 / 刹停 |
| Space | 跳跃 |
| J | 连击，在当前出招后再按可接下一段 |
| K | 重击，消耗体力，打断首领蓄力 |
| L / Shift | 闪避，有短暂无敌时间 |
| U | Lv.2 解锁，消耗 60 专注释放碎片冲击 |
| Tab | 营地 / 当前战斗 |
| Esc | 暂停 |
| P | 返回原生桌宠，再进入可恢复当前会话 |

## 约束与实际边界

这是原图驱动的二维动作实现，不是完整重绘或完整三维绑定。脸与躯干保持比例；四肢必须发生关节运动，不能把“所有像素完全静止”当作动作目标。肩部尚受原图视角和遮挡限制，大幅转身、背面或复杂摔投仍需要额外的正式动作资产。

本轮没有重新生成奶蛙，也没有改原生桌宠的素材、程序、菜单或黑框/透明实现。所有文件投喂仍是游戏虚拟数据。

森林与敌人是此前的探索资产，作为当前二维战斗场景接入，不将它们宣称为已获用户认可的最终美术，也不宣称完成了此前提出的全项目三维赛璐璐方向。

独立动画验证场继续保留。修改标准角色脚本后可运行 `python tools/sync_animation_lab.py` 同步，避免两个入口的动作实现分叉。
